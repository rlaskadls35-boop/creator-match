## 1. 목적과 범위

### 1.1 해결하려는 문제

광고주가 캠페인 예산, 카테고리, 원하는 크리에이터 규모를 입력하면, 제공된 크리에이터 200명 데이터에서 조건에 맞는 후보를 찾아 근거와 함께 순위로 보여주는 웹 프로토타입.

### 1.2 사용자 (두 역할)

| 역할 | 하는 일 | 진입 |
|---|---|---|
| 광고주 | 조건 입력, 결과 확인, 정렬·필터, 추천 이유 확인 | 첫 화면, 로그인 없음 |
| 운영자 | 매칭 점수의 항목 비중 조절, 결과 미리보기, 저장 | 목업 로그인 후 `#/admin` |

### 1.3 범위 밖 (의도적으로 제외)

- 캠페인 전체 총예산을 여러 명에게 배분하는 조합 추천 (예산은 1인 예산으로만 해석)
- 실제 인증·권한 관리 (로그인은 역할 분리를 보여주는 목업)
- 서버·DB. 운영자 설정은 브라우저 저장소에만 유지된다
- 카테고리 간 유사도(뷰티↔패션 등) 정의
- 이력 없는 크리에이터의 단가를 팔로워 수 기반으로 회귀 추정하는 것 (구간 중앙값으로 단순 추정)

### 3.2 데이터에서 확인한 사실 (설계 근거)

- 팔로워 분포: 1.5만/10만 경계에서 나노 101명 / 마이크로 72명 / 매크로 27명. 기존 1만/10만의 44 / 129 / 27명에서 작은 마이크로 57명이 나노로 이동
- 현재 집단별 최대/최소 팔로워 배수: 나노 4.94배 / 마이크로 5.42배 / 매크로 4.06배. 업계 표준이나 매칭 정확도 향상 검증을 뜻하지 않음
- 이력이 있는 사람의 단가 범위: 나노 21만~196만, 마이크로 52만~200만, 매크로 224만~679만 원. 나노와 마이크로 단가는 겹침
- 참여율은 팔로워가 클수록 낮음 (log 팔로워와 상관 −0.59). 중앙값 나노 7.4%, 마이크로 7.0%, 매크로 5.0%
- 희소 조합 존재: 매크로 피트니스·게임·교육 각 1명
- 이력 있는 173명의 평점 평균 4.42, 범위 3.4~5.0
- 조회수/팔로워 비율 0.07~0.71

### 3.3 읽기·정제 규칙

1. 파일을 문자열로 읽고 맨 앞 BOM(U+FEFF, 보이지 않는 문자)을 제거한다
2. CRLF/LF 모두 처리한다 (CSV 파서 사용: PapaParse)
3. 헤더 11개가 기대와 다르면 로드 실패 메시지를 화면에 표시한다
4. 행 검증: creator_id·creator_name·category·platform 비어 있으면 건너뜀. followers, avg_view_count, engagement_rate, total_campaign_count, total_campaign_budget_krw, avg_campaign_budget_krw가 비었거나 숫자가 아니거나 음수면 건너뜀. category가 10종 밖이거나 platform이 2종 밖이면 건너뜀
5. advertiser_rating: 공란 또는 공백 → `null`. 숫자면 그대로. 0~5 범위 밖이면 행 건너뜀
6. 건너뛴 행 수를 기록하고 화면 하단 데이터 상태 줄에 표시한다 (0이면 표시 생략)
7. 원본 파일은 절대 쓰지 않는다. 정제 결과는 메모리 안의 파생 객체로만 존재한다

### 3.4 파생 필드 (크리에이터마다 계산)

| 필드 | 계산 |
|---|---|
| tier | followers < 10,000 → 나노; < 100,000 → 마이크로; 그 외 → 매크로 |
| hasHistory | total_campaign_count > 0 |
| rate (단가) | hasHistory면 avg_campaign_budget_krw, 아니면 같은 tier의 이력 있는 사람들의 avg_campaign_budget_krw 중앙값 |
| rateIsEstimated | !hasHistory |
| rating (평점) | advertiser_rating이 있으면 그 값, 없으면 이력 있는 전체의 평균 (소수 둘째 자리) |
| ratingIsEstimated | advertiser_rating == null |
| costPerView (조회 1회당 평균 비용) | rate ÷ avg_view_count (원). 낮을수록 좋음 |

중앙값·평균은 로드 시 데이터에서 계산한다. 상수로 박지 않는다.

## 5. 추천 로직

### 5.1 1단계: 필터

입력: platform(전체/유튜브/인스타그램 중 1), budget(원, 양수 정수), categories(1개 이상), tier(나노/마이크로/매크로 중 1).

후보 = 모든 크리에이터 중 다음을 모두 만족하는 사람
- category ∈ categories
- tier == 입력 tier
- platform == 입력 platform (`전체`이면 양쪽 플랫폼 허용)
- rate ≤ budget (이력 없으면 예상 단가 기준)

"이력 있는 사람만"은 검색 결과에 추가로 적용되는 결과 화면 필터다. 후보 0명 판정(5.7)과 조건 완화는 플랫폼까지 포함한 검색 조건을 기준으로 한다.

### 5.2 규모 구간

| 구간 | 기준 | 근거 |
|---|---|---|
| 나노 | followers < 15,000 | 14,953명과 18,445명 사이에 경계를 두어, 현재 세 집단의 내부 팔로워 격차를 약 4~5배로 완화. 인원 균등 배분을 목표로 하지 않는 자체 기준 (L28) |
| 마이크로 | 15,000 ≤ followers < 100,000 | 기존 집단의 약 10배 격차를 약 5.4배로 완화 |
| 매크로 | followers ≥ 100,000 | 메가(100만 이상) 해당자가 없어 선택지에서 제외 |

경계값은 "이상"이 위 구간. 유튜브 구독자와 인스타그램 팔로워는 같은 숫자로 취급.

### 5.3 항목 5개와 비교 집단

| 항목 | 원본 | 방향 | 비교 집단 |
|---|---|---|---|
| 참여율 | engagement_rate | 높을수록 좋음 | 같은 tier |
| 평균 조회수 | avg_view_count | 높을수록 좋음 | 같은 tier |
| 광고주 평점 | rating (예상 포함) | 높을수록 좋음 | 전체 200명 |
| 캠페인 건수 | total_campaign_count | 많을수록 좋음 | 전체 200명 |
| 조회 1회당 평균 비용 | costPerView | 낮을수록 좋음 | 같은 tier |

같은 tier로 비교하는 이유: 세 값은 규모에 따라 구조적으로 달라진다. 전체와 비교하면 규모 차이가 실력 차이처럼 점수에 찍힌다. 평점·건수는 규모와 무관하므로 전체 기준.

카테고리는 비교 집단으로 쓰지 않는다 (칸이 1~2명이 되어 등수가 무의미).

비교 집단은 항상 데이터 전체(또는 tier 전체)이며 검색 결과 안이 아니다. 그래야 "상위 10%"의 뜻이 검색과 무관하게 일정하다.

### 5.4 항목 점수 (백분위)

각 항목에 대해, 비교 집단 안에서:

```
상위 %  = (나보다 좋은 사람 수 + 동점자 수 ÷ 2) ÷ (집단 인원 − 1) × 100
항목 점수 = 100 − 상위 %
```

- "좋은"은 항목의 방향을 따른다 (비용은 낮은 쪽이 좋음)
- 집단 인원이 1명이면 항목 점수 50
- 항목 점수는 소수 첫째 자리까지 유지하고 합산 후에만 반올림한다
- 화면 표시용 "상위 N%"는 `max(1, round(상위 %))`
- 항목 점수는 로드 시 전원에 대해 1회 계산해 둔다 (검색과 무관)

검증용 예시 (민준브이로그180, 마이크로): 참여율 59.0 / 평균 조회수 53.1 / 광고주 평점 74.9 / 조회 1회당 비용 71.1 / 캠페인 건수 93.7 → 비중 30/25/20/15/10으로 매칭 점수 65.99 → 표시 66. (2026-09-12 구현 세션에서 평점 보정 없이 재계산한 값. 브레인스토밍 시 계산(79.4 / 66.9 → 67)은 보정 포함이었음. L21)

### 5.5 매칭 점수

```
매칭 점수 = Σ (항목 점수_i × 비중_i ÷ 100)     비중 합 = 100
```

- 표시는 반올림 정수 0~100
- 기본 비중(임시): 참여율 30, 평균 조회수 25, 광고주 평점 20, 조회 1회당 비용 15, 캠페인 건수 10
- 비중 논리: 구독자 품질(참여율+조회수) 55, 실적(평점+건수) 30, 비용 15
- 운영자가 저장한 비중이 있으면 그것을, 없으면 기본 비중을 쓴다
- 동점 정렬: 매칭 점수 → 참여율 → creator_id 순

### 5.6 예상값 규칙 (이력 없는 27명)

- 예상 단가 = 같은 tier의 이력 있는 사람들의 avg_campaign_budget_krw 중앙값. 예산 필터와 비용 항목 계산에 사용
- 예상 평점 = 이력 있는 전체의 advertiser_rating 평균. 평점 항목 계산에 사용
- 캠페인 건수 0은 사실이므로 그대로 반영 (이것이 신규가 자연스럽게 낮게 깔리는 장치)
- 화면: "캠페인 이력 없음" 배지, 평점·단가 자리에 "예상 ~ ⓘ" 표시와 툴팁. 별 아이콘은 그리지 않는다
- 이 사람들의 추천 이유 칩에는 평점·건수 항목을 뽑지 않는다 (참여율·조회수·비용 중에서만)
- 이 사람들의 유의점에는 건수를 넣지 않는다 (배지가 이미 말함)

### 5.7 후보가 없거나 적을 때

A = category ∈ categories 이고 tier == 입력 tier 인 사람 (예산 무시).

후보 0명이면 결과 영역에 세 덩이를 순서대로 표시:

1. 원인 진단 한 줄
   - A가 비어 있으면: "선택한 카테고리에는 {tier} 크리에이터가 없습니다."
   - A가 있으면: "{카테고리들} 카테고리의 {tier} 크리에이터는 {|A|}명 있지만, 모두 단가가 예산 {예산}을 넘습니다. 가장 낮은 단가는 {A의 최저 rate}입니다."
2. 조건 완화 버튼 (누르면 그 조건으로 즉시 재검색)
   - 예산 올리기: A가 있을 때만. 제안 예산 = A의 최저 rate. 인원 = A 중 rate ≤ 제안 예산인 수. 문구 "예산을 {제안}으로 올리면 → {n}명"
   - 규모 바꾸기: 다른 두 tier 각각. 인원 = category ∈ categories, tier == 그 tier, rate ≤ budget 인 수. 0명이면 비활성(회색)으로 두고 "최저 단가 {그 tier·카테고리의 최저 rate}" 표기. 그 조합 자체가 없으면 "해당 크리에이터 없음"
   - 카테고리 넓히기: 인원 = tier == 입력 tier, rate ≤ budget 인 수 (카테고리 무시). 0명이면 비활성 + 최저 단가 표기
3. 조건에 가장 가까운 크리에이터 (표)
   - 집합 = 세 조건 중 정확히 하나만 어긋나는 사람들의 합집합
     - 카테고리·규모 맞고 예산만 초과 → "예산을 {rate} 이상으로"
     - 카테고리·예산 맞고 규모만 다름 → "규모를 {그 사람 tier}로"
     - 규모·예산 맞고 카테고리만 다름 → "카테고리에 {그 사람 category} 추가"
   - 매칭 점수 내림차순 상위 3명. 열: 순위, 크리에이터, 매칭 점수, 참여율, 평균 조회수, 단가, 이렇게 바꾸면 섭외 가능
   - 집합이 비면 이 덩이는 생략

극단 입력: 전체 크리에이터 중 rate ≤ budget 인 사람이 아무 tier·카테고리에도 없으면 진단 문구 뒤에 "전체 크리에이터의 최저 단가는 {전체 최저 rate}입니다." 추가.

후보가 1~2명이면 결과 표 아래에 2번 덩이(완화 버튼)를 작게 붙이고 제목을 "후보가 적습니다. 조건을 넓히면 더 볼 수 있습니다."로 한다.

조건은 절대 자동으로 완화하지 않는다. 모든 완화는 광고주가 버튼을 눌러 선택한다.

### 5.8 추천 근거

각 후보에 대해:

- 강점 칩 최대 3개: 항목 점수가 높은 순으로 3개 (이력 없음은 참여율·조회수·비용 중에서). 문구 형식
  - 참여율: "참여율 상위 {N}% ({tier} 기준)"
  - 평균 조회수: "평균 조회수 상위 {N}% ({tier} 기준)"
  - 광고주 평점: "광고주 평점 {값}, 전체 상위 {N}%"
  - 캠페인 건수: "캠페인 경험 {n}건, 전체 상위 {N}%"
  - 비용: "조회 1회당 {원}원, {tier} 상위 {N}%"
- 유의점: 항목 점수 25 미만인 항목마다 한 줄. "유의점: {항목}은 {tier 또는 전체} 중 하위권입니다 ({원본값})". 여러 개면 모두 표시
- 항목 점수 막대 5개: 항목명, 막대(0~100), 항목 점수(정수), "{집단} {인원}명 중 {등수}등". 비중은 표시하지 않는다

### 5.9 원칙: 비중은 합산에만

항목 점수, 강점 칩, 유의점, 배지, 예상값은 데이터로만 결정된다. 운영자가 비중을 바꾸면 매칭 점수와 순위만 달라진다. 알려진 한계: 한 항목에 극단적 비중을 몰면 순위가 높은 이유와 강점 칩이 어긋날 수 있다. 운영자 화면의 경고 문구로 다룬다.

### 5.10 정렬·필터

| 정렬 | 기준 | 이력 없음 위치 |
|---|---|---|
| 매칭 점수 높은 순 (기본) | 매칭 점수 desc | 점수대로 섞임 |
| 참여율 높은 순 | engagement_rate desc | 섞임 |
| 평균 조회수 높은 순 | avg_view_count desc | 섞임 |
| 광고주 평점 높은 순 | rating desc | **맨 아래** (예상값이라) |
| 캠페인 건수 많은 순 | count desc | 자연히 맨 아래 |
| 단가 낮은 순 | rate asc | 예상 단가로 섞임 |

- 열 제목 클릭으로 정렬. 같은 열을 다시 누르면 방향 반전. 현재 정렬 열에 화살표 표시
- 순위 열은 현재 정렬 순서대로 1부터 다시 매김. 매칭 점수 순이 아닐 때 순위 열 제목을 "순위 ({기준} 기준)"으로 표시
- 매칭 점수는 정렬과 무관하게 그대로 표시된다
- 필터: 플랫폼(전체/유튜브/인스타그램), "캠페인 이력 있는 크리에이터만" 체크. 결과 제목의 N은 필터 적용 후 인원

## 7. 기술 구조

- Vite + React 18 + TypeScript. 테스트 Vitest (+ @testing-library/react 최소 사용)
- CSV 파싱: PapaParse (SQLite 생성 시에만 사용, L27)
- 라우팅: 해시 라우터 (`#/`, `#/login`, `#/admin`). GitHub Pages에서 새로고침 404를 피하기 위함. 의존성 없이 `window.location.hash` 직접 처리
- 데이터 로드 (L27): 원본 CSV는 읽기만 하며 SHA-256으로 보존을 검증한다. 실행·빌드·테스트 전에 `npm run db:build`로 `data/creators.sqlite`를 준비하고, 브라우저에서 sql.js(WASM)로 실제 SQLite 파일을 조회한다. SQLite와 WASM은 Vite가 같은 사이트의 정적 자산으로 배포한다. DB에는 원본 11개 필드와 검증 메타데이터를 저장하고 평점 공란은 SQL NULL로 보존한다. 파생값·통계·점수는 기존 규칙으로 계산한다. 로드 중 안내 및 오류 시 재시도를 제공한다.
- 상태: React state. 운영자 비중·세션은 `localStorage` (`creator-match.weights`, `creator-match.admin-session`). 읽기·쓰기 모두 try/catch, 없으면 기본값

## 8. 테스트 (Vitest, `src/domain/*.test.ts`)

최소 다음을 자동 테스트로 증명한다.

1. parseCreators: BOM 있는 문자열에서 첫 컬럼이 `creator_id`로 읽힌다 / CRLF 처리 / 200명 로드 / 평점 공란 27명이 `null` / 이력 없음 27명 = 건수 0 / 숫자 칸에 문자가 있는 행은 건너뛰고 카운트된다
2. tiers: 10,000·14,999→나노, 15,000·99,999→마이크로, 100,000→매크로 / 실제 데이터에서 101·72·27명
3. 파생값: 규모별 참고 단가 중앙값은 나노 700,000 / 마이크로 1,320,000 / 매크로 4,725,000 / 신규 개인의 평점·단가·비용은 null 유지 / costPerView = rate ÷ views
4. percentile: 1등 100, 꼴등 0, 동점자 절반 규칙, 집단 1명이면 50, 방향 반전(비용)
5. scoring: 비중 30/25/20/15/10에서 민준브이로그180의 항목 점수와 매칭 점수가 계산값과 일치 / 비중 합 검증(100 아니면 오류) / 비중을 바꾸면 순위가 바뀐다
6. recommend 필터: 뷰티+패션 / 마이크로 / 150만 → 이력 후보 6명 / 1위 정은매거진77의 매칭 점수 72.839 (표시 73점) / 예산 경계(rate == budget 포함)
7. 후보 0명: 뷰티 / 매크로 / 50만 → 진단 문구가 "4명 있지만 …" 형식, 예산 제안 = 3,010,000 / 규모 바꾸기 나노 3명·마이크로 0명(비활성, 최저 단가 540,000 — 뷰티·마이크로 조합의 최저. L21) / 카테고리 넓히기 0명 / 근접 후보 3명이고 각 행에 "이렇게 바꾸면" 문구가 있다 / 카테고리에 해당 tier가 없는 케이스 문구 / 극단 예산(5만) 시 전체 최저 단가 문구
8. explain: 강점 칩 3개가 항목 점수 상위 3개 / 이력 없음은 평점·건수 칩 없음 / 항목 점수 25 미만이면 유의점 생성 / 상위 % 표시 최소 1
9. 정렬: 평점순에서 이력 없음이 맨 아래 / 단가 낮은 순에서 예상 단가가 섞여 정렬 / 동점 처리
10. weights 저장소: 저장→읽기 왕복, 손상된 값이면 기본값

화면 테스트는 스모크 1개(광고주 화면 렌더, 검색 후 결과 표 표시)만 둔다. 나머지는 실행 화면을 사용자가 직접 확인한다.
