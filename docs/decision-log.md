# 결정 기록 (Decision Log)

브레인스토밍과 구현 과정에서 내려진 결정을 시간순으로 남긴다. 각 항목은 "AI(Claude Code)가 무엇을 제안했고, 사용자(김태홍)가 어떻게 판단해 무엇으로 결정됐는지"를 적는다. AI_USAGE.md를 쓸 때 이 파일을 근거로 삼는다.

표기: **AI** = Claude Code 제안, **사용자** = 지원자 판단, **결과** = 최종 결정.

## 2026-09-11 (브레인스토밍 1일차)

### L01. 진행 방식: 질문 도구 대신 채팅
- AI: 선택지를 UI 질문 도구(AskUserQuestion)로 제시
- 사용자: "질문 도구 사용하지 말고 채팅으로 진행하자"
- 결과: 모든 질문·선택지를 채팅 텍스트로. 이후 세션에도 적용되도록 메모리에 저장

### L02. 데이터 프로파일링 선행
- AI: CSV를 그대로 쓰지 않고 먼저 전수 분석 (BOM·CRLF, 공란 27건 = 캠페인 0건 27명 동일 집단, avg_campaign_budget ≠ total/count, 팔로워 분포의 빈 구간, 구간별 단가 비겹침, 참여율-팔로워 음의 상관, 희소 조합)
- 사용자: 분석 결과를 근거로 이후 결정 진행
- 결과: 설계 문서 3.2절의 근거가 됨

### L03. 예산의 의미
- AI: 3안 제시 (1인 캠페인 예산 / 총예산 / 둘 다) + 1안 추천
- 사용자: "크리에이터 1인 캠페인 예산이 맞아"
- 결과: D1. 총예산 배분은 범위 밖으로 명시

### L04. 이력 없는 크리에이터 처리 (1차)
- AI: 3안 (한 리스트에서 보수적 추정 / 별도 구역 / 체크박스 제외) + 1안 추천. 단, 1안 설명이 어려워 사용자가 "이해하기 쉽게 다시" 요청 → 예시로 재설명
- 사용자: 단가 추정은 납득. 단, **"평점을 임의로 산정해서 별점을 주는 건 아니라고 생각해. 0점을 주면 어떤 부작용이 있는지 말해줘"**
- AI: 실제 데이터로 시뮬레이션 (0점: 신규 27명 전원 141~200위, 실제 최저 평점 3.4점인 사람들보다도 아래 / 평균 채움: 60위까지 / 항목 제외+감점: 85위까지) 표로 제시. 화면에 가짜 별점을 그리지 않는다는 점은 사용자 지적이 맞다고 인정. 대안으로 "평점 항목 제외 + 미검증 감점" 제안
- 사용자: 설명을 다시 듣고 **"예상 평점이라는 배지를 두면 광고주가 판단하기 오히려 좋다. 마우스 오버 툴팁으로 산정 근거를 알리자"**
- 결과: D11. 예상 평점 배지 + 툴팁. "추정치는 항상 라벨 + 툴팁" 원칙이 예상 단가에도 적용됨 (D12)
- AI_USAGE 관점: AI가 처음 제안한 "계산에만 쓰고 화면엔 평점 없음"보다 사용자의 "예상이라 밝히고 보여주기"가 광고주 판단에 더 유리하다고 판단한 사례

### L05. 참여율의 의미 확인
- 사용자: "참여율이 크리에이터가 캠페인에 참여하는 비율인지, 구독자의 참여율인지?"
- AI: 구독자(시청자) 참여율. 값 범위(3~8.9%)와 팔로워와의 음의 상관(−0.59)이 그 해석을 뒷받침
- 결과: 용어 확정. PRD 용어 정의 후보

### L06. 팔로워 구간 기준
- AI: 1만/10만 컷 제안 (업계 관행 + 데이터 빈 구간 + 단가 비겹침)
- 사용자: "통상 기준이 정말 그런지 웹에서 검색해서 말해봐"
- AI: 국내외 8개 자료 확인. 나노 <1만, 마이크로 1만~10만, 매크로 10만~100만, 메가 100만+ 로 일치. 공식 표준은 없음
- 사용자: "PRD에 '실서비스라면 100만 이상 분리한다'라고 적지 마"
- 결과: D5. 메가는 해당자 없어 제외한 사실만 기재
- AI_USAGE 관점: AI 주장을 그대로 받지 않고 외부 검증을 요구한 사례

### L07. 문서 내용 승인 규칙
- 사용자: **"PRD에 적을 내용을 임의로 정하지 말고, 무엇을 어떻게 적을지 내 확인을 꼭 받아라"**
- 결과: D30. 문서마다 항목별 초안 목록 → 승인 → 작성. 메모리에 저장

### L08. 점수 항목 5개
- AI: 과제가 명시한 4개(참여율·조회수·평점·건수) + 비용 효율 1개
- 사용자: 5개 동의. 단, "비용 효율"에 대해 **"평균 조회수 ÷ 단가라면 실측이 아니라 평균 기반이니 '평균 비용 효율'이 맞지 않나?"**
- AI: 맞는 지적. 계산식에 먼저 눈이 가서 사용자에게 어떻게 읽힐지를 놓쳤다고 인정. 이름 2안 제시
- 사용자: "조회 1회당 평균 비용"으로. 이어 "왜 이 항목을 추천했나?" → AI가 근거(예산 필터는 이하/초과만 보므로 같은 예산 안의 효율 차이를 못 잡음. 실제 데이터에서 22원 vs 146원 6배 차이) 와 반대 논거(과제 명시 항목 아님, 조회수와 일부 중복) 를 함께 제시
- 사용자: 넣기로 결정. 계산식(700,000 ÷ 8,279 = 84.6원) 확인
- 결과: D6. 이름 "조회 1회당 평균 비용", 낮을수록 좋음
- AI_USAGE 관점: 업계 용어(CPV/비용 효율)를 그대로 쓴 AI 표현을 사용자가 "추정치임이 드러나야 한다"고 바로잡은 사례. L04와 같은 원칙

### L09. 비교 방법 (백분위, 비교 집단)
- AI: 항목별 "상위 몇 %" 변환. 참여율·조회수·비용은 같은 규모 안, 평점·건수는 전체
- 사용자: 여러 차례 "이해 안 간다" → AI가 학교 등수, 수능 백분위 비유로 재설명. "광고주 입력 필터와 전체 기준 등수가 상충하지 않나?" → 필터(누구를 보여줄지)와 등수(각자가 얼마나 좋은지)는 별개이며, 결과 안에서 등수를 매기면 후보 1명이 항상 상위 1%가 되는 문제가 있음을 설명. "카테고리는 비교 집단으로 안 쓴다"의 뜻도 재설명(칸이 1~2명이 되어 등수 무의미)
- 결과: D7
- AI_USAGE 관점: 사용자가 이해될 때까지 반복 질문한 구간. 최종적으로 사용자가 "면접에서 말로 설명할 수 있는 수준"을 요구 → AI가 30초 설명과 예상 질문 답안을 정리

### L10. 합산 점수 이름
- AI: "추천 점수" 추천, 대안 "매칭 점수", "종합 점수"
- 사용자: "매칭 점수가 더 나은 것 같아"
- 결과: D8. AI 추천안이 아닌 사용자 선택

## 2026-09-12 (브레인스토밍 2일차)

### L11. 비중 결정 방식: 운영자 슬라이더
- AI: 비중 30/25/20/15/10을 코드 기본값으로 제안
- 사용자: **"비중을 관리자 화면에서 슬라이더로 직접 조절하고 결과를 보면서 정하자. 로그인 환경을 만들고 사용자 화면에서는 조절이 보이지 않게"**
- AI: 아이디어 채택. 단, 로그인은 정적 사이트라 진짜 인증이 불가하고 가짜 로그인은 감점 위험이라며 반대
- 사용자: **"평가자는 로컬에서 실행해 볼 거고 라이브 서비스가 아닌데 왜 안 되나?"**
- AI: 입장 수정. "보안 장치"가 아니라 "두 역할이 있다는 화면 구성"으로 보면 의미가 있고, "프로토타입용 임시 계정"이라고 명시하면 오해가 없다고 판단. 목업 로그인 제안
- 결과: D23, D24. 사용자 아이디어 + AI의 한계 명시(브라우저 저장소에만 유지, 실제 인증 아님)
- AI_USAGE 관점: AI가 과도하게 반대한 것을 사용자가 논리로 뒤집은 사례

### L12. 광고주 화면에 비중 표시 여부
- AI: 점수 막대 옆에 비중을 읽기 전용으로 표시 제안 (설명 가능성 가산점)
- 사용자: "광고주 화면에는 보여줄 이유가 없다"
- 결과: D10

### L13. 평점 보정(소수 표본 축소) 제거
- AI: 캠페인 1~3건인 사람의 평점을 평균 쪽으로 당기는 보정 제안. 계산식 설명(가상 캠페인 3건)
- 사용자: 설명이 어려워 두 번 재요청. 이해 후 **"왜 평점을 굳이 평균으로 보정해야 하나? 1건에 5.0이면 광고주가 그걸 보고 판단하면 되는 것 아닌가? 과제의 예외 처리 요구 때문인가?"**
- AI: 두 가지를 분리해 답변. (가) 공란 평점 → 4.4 채움은 과제의 Null Safety 요구 (0은 "최악", 공란은 "모름"이라 다름). (나) 보정은 AI가 덧붙인 것이며 과제 요구 아님. 재검토 결과 캠페인 건수가 이미 점수 항목(10)에 있어 "1건 5.0이 30건 4.8을 이기는 문제"를 이미 막고 있음 → 이중 처리. **보정 제거로 제안 변경**
- 사용자: "4.4는 왜?" → AI: 데이터의 실제 평균이며 0/2.5/5와 비교표로 이유 설명. 사용자 "평점 없는 사람들에게 인식값을 부여하는 거지?" → 맞음
- 결과: D11(예상 평점 4.4 유지), D14(보정 없음)
- AI_USAGE 관점: 사용자 질문으로 AI가 자기 제안의 불필요함을 발견해 철회한 사례. 설명 단순화 효과

### L14. 후보 0명 화면
- AI: 3덩이(원인 진단 / 완화 버튼+인원수 / 조건 하나만 다른 근접 후보 3명) 제안. 사용자 요청으로 텍스트 화면 목업 제시
- 사용자: 이해 후 "이렇게 하는 게 좋은 이유를 다시 생각해서 답해봐"
- AI: 광고주의 질문 순서(왜 없지 → 뭘 바꾸지 → 바꾸면 누구) 에 대응, 자동 완화 금지 원칙, 3명 제한 이유, 트레이드오프 설명
- 결과: D16
- 이후(L18) 근접 후보 표의 열 이름 재논의

### L15. 추천 근거 표시
- AI: 강점 칩 3개 + 유의점(하위 25%) + 항목 점수 막대. 카드 목업 제시
- 사용자: OK. 이후 시안을 보고 "'참여율은 마이크로 중 하위권이에요 (6.5%)'가 뭐냐, 합의한 내용이 아닌 것 같다" → AI가 6번에서 합의한 유의점 줄임을 상기시키고 근거(좋은 점만 나열하면 못 믿음) 재설명. 1위인 정은매거진77이 참여율 하위권인데 1위인 이유(다른 4항목 최상위, 비중 계산표) 설명
- 사용자: "관리자 슬라이더를 조절하면 유의점도 바뀌나? 그 로직도 설계에 들어가나?"
- AI: 비중은 합산에만 쓰이고 항목 점수·칩·유의점·배지는 데이터로만 결정 → 순위·점수는 바뀌지만 유의점은 불변. 극단 비중 시 순위 이유와 강점 칩이 어긋날 수 있는 한계와 대안(기여 점수 기준 칩)의 단점 설명
- 사용자: 유의점 유지 확정
- 결과: D17, D25

### L16. 정렬·필터
- AI: 정렬 6기준, 필터 2개, 평점순에서 이력 없음 맨 아래, 순위 표시에 정렬 기준 붙이기
- 사용자: "정렬하면 매칭 점수가 다시 계산되어야 하지 않나? 관리자 비중과 헷갈린다"
- AI: 정렬은 순서만, 점수는 불변. 운영자(비중)/광고주 정렬/광고주 필터의 역할 표로 설명
- 결과: D18~D20

### L17. 화면 구조와 시안

- 사용자: **"UX상 상하 분할이 맞다. 관리자 화면도 같은 구조에 슬라이더를 상단에"** → AI 재작성
