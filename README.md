# Creator Match

모비데이즈 과제를 작은 단위로 구현하는 Next.js · React · TypeScript 프로젝트입니다.

## 로컬 실행

Node.js **22.13.0 이상**에서 `npm install` 후 `npm run dev`를 실행하고 http://127.0.0.1:3000 에 접속합니다. 화면 변경은 개발 서버에 자동 반영됩니다.

Node.js 내장 `node:sqlite`를 사용하므로 별도 DB 서버 설치나 계정 설정은 필요하지 않습니다. 해당 모듈을 플래그 없이 사용할 수 있는 최소 버전은 22.13.0입니다. [Node.js 공식 문서](https://nodejs.org/api/sqlite.html)

`npm run dev`, `npm run build`, `npm start` 실행 전 SQLite 초기화가 자동으로 수행됩니다. 최초 실행에서는 DB 파일과 테이블을 만들고 CSV를 적재합니다. 이후에는 같은 ID를 갱신하므로 중복되지 않습니다. 수동으로 다시 적재하려면 `npm run db:init`을 실행합니다. 초기화에 실패하면 서버 실행이나 빌드도 중단됩니다.

프로덕션 실행은 `npm run build` 후 `npm start`입니다. 로컬 Node.js 서버와 파일 기반 SQLite 구성이며, 별도 배포 서비스는 이번 범위에 포함하지 않습니다.

## 현재 구현 범위

- 원 단위 예산 입력, 천 단위 쉼표, 빠른 금액 추가
- 10개 카테고리가 펼쳐진 다중 선택 버튼
- 플랫폼 단일 선택: 전체(기본값) / 유튜브 / 인스타그램. 초기화 시 전체로 복귀.
- 팔로워 규모 단일 선택: 나노 1만 미만 / 마이크로 1만 이상 10만 미만 / 매크로 10만 이상
- 필수 입력 검증, 초기화, 반응형 화면
- 항목명과 입력값을 가로로 정렬한 입력 폼. 16px 선택값, 진한 글자, 44px 버튼으로 구성하며 모바일에서는 세로 정렬.

- 조건 확인 시 서버가 SQLite에서 검색한 크리에이터 결과표 표시. 조건에 맞는 결과가 없으면 빈 상태 안내.
- 결과표: 크리에이터 / 플랫폼 / 카테고리 / 평균 진행 예산 / 팔로워 수 / 평균 조회수 / 참여율 / 누적 캠페인 건수 / 광고주 평점. 내부 ID는 노출하지 않음.

예산은 크리에이터 1명의 과거 평균 진행 예산(`avg_campaign_budget_krw`)이 입력 금액 이하인 후보를 찾는 상한입니다. 현재 확정 견적이나 여러 명의 예산 합계를 의미하지 않습니다. 캠페인 이력이 없거나 평균 예산이 0원인 후보는 예산을 확인할 수 없으므로 결과에서 제외하고 인원수를 안내합니다. 빈 평점은 0점 대신 ‘평가 없음’으로 표시합니다.

복수 카테고리는 선택한 항목 중 하나에 해당하면 통과하며, 플랫폼과 팔로워 규모 및 예산 조건을 모두 만족해야 결과에 포함됩니다. 결과는 CSV의 원래 순서를 유지하며 점수 산정이나 추천 순위는 아직 적용하지 않습니다.

입력 조건을 변경하거나 초기화하면 기존 결과가 사라지고, 조건 확인하기를 다시 눌러 갱신합니다. 입력은 현재 화면의 메모리에만 유지되며 새로고침하면 초기화됩니다. 원본 CSV는 수정하지 않았습니다.

## 데이터 저장 및 조회

원본 `dummy_creators.csv` → 검증 및 적재 → `data/creator-match.sqlite`의 `creators` 테이블 → `POST /api/creators`에서 조건 조회 → 결과표 순서로 동작합니다. 최초 화면에는 크리에이터 전체 데이터를 전달하지 않습니다. 검색할 때 일치하는 후보와 예산 미확인 제외 인원만 반환합니다.

| 저장 항목 | SQLite 타입과 제약 |
| --- | --- |
| `creator_id` | TEXT, 기본 키, 공란·중복 불가. 화면에는 숨김 |
| `creator_name` | TEXT, 필수 |
| `category`, `platform` | TEXT, 정의된 선택값만 허용 |
| `followers`, `avg_view_count`, `total_campaign_count` | INTEGER, 0 이상. 공란은 NULL |
| `total_campaign_budget_krw`, `avg_campaign_budget_krw` | INTEGER, 원 단위, 0 이상. 공란은 NULL |
| `engagement_rate` | REAL, 0~100. 공란은 NULL |
| `advertiser_rating` | REAL, 0~5. 공란은 NULL |

CSV의 11개 컬럼을 하나의 STRICT 테이블에 보관합니다. 누적 예산처럼 화면에서 사용하지 않는 값도 저장하며, 평균 예산을 누적 예산/건수로 재계산하거나 원본 수치를 임의로 수정하지 않습니다. 팔로워 구간은 조회 시 계산하며, 화면의 구간 안내와 서버의 검색 기준은 같은 정의를 사용합니다.

DB 파일은 CSV에서 재생성할 수 있는 생성물이므로 Git에 포함하지 않습니다. 원본 CSV, 테이블 생성 코드, 검증 및 적재 코드는 Git으로 관리합니다. 적재는 동일 ID를 갱신하거나 새 ID를 추가하며 기존 ID를 삭제하지 않습니다. 현재 원본 200명을 기준으로 사용합니다.

## 안전한 데이터 처리

- 적재 전 CSV의 컬럼·중복 ID·필수 정보·허용 선택값·숫자 형식과 범위를 모두 검사합니다. 잘못된 값은 0이나 추정값으로 바꾸지 않고 행과 항목을 알려 적재를 중단합니다.
- 전 행 검증 후 트랜잭션으로 적재합니다. DB 오류가 나면 해당 적재 작업 전체를 롤백하여 이전 데이터가 유지됩니다. DB 제약조건도 타입·중복·음수·범위를 검사합니다.
- 공란은 NULL로 저장하고, 평점 NULL을 0점으로 계산하지 않습니다. 누적 캠페인 건수가 0인데 평점이 있는 모순된 데이터는 적재를 중단합니다.
- 원본 평균 예산 0원은 그대로 보관합니다. 조회 시에는 캠페인 건수가 양수이고 평균 예산도 양수인 데이터만 예산 내 후보로 사용합니다. 건수나 예산이 0 또는 NULL이면 예산 미확인 제외 인원으로 별도 안내합니다.
- 팔로워 수가 NULL이면 규모를 판단할 수 없으므로 규모 필터를 통과시키지 않습니다. 10,000명은 마이크로, 100,000명은 매크로에 포함합니다.
- 서버에서도 입력 예산·카테고리·플랫폼·규모를 검증하고 SQL 매개변수를 바인딩합니다. 잘못된 요청은 400, DB 조회 실패는 500으로 응답하여 정상적인 결과 0명과 구분합니다.
- 조회 중에는 버튼에 진행 상태를 표시합니다. 조회 실패는 재시도 안내를 표시하며, 조건 변경·초기화 시 진행 중 요청을 취소하고 이전 조건의 늦은 응답을 무시합니다.

SQLite는 별도 서버 없이 실행·재현할 수 있다는 장점이 있습니다. 대신 초기 적재 단계와 Node.js 서버가 필요합니다. 이 과제의 200명 규모에서는 성능 향상보다는 저장·검증·조회 역할을 명확히 나누기 위한 선택입니다.

## 검증 명령

`npm test`, `npm run lint`, `npm run typecheck`, `npm run build`

테스트는 메모리 SQLite를 사용해 원본 보존, 200행 적재, 재적재, NULL, 숫자 검증, 트랜잭션 롤백, 필터 경계와 API 입력 검증을 확인합니다. 실행 중인 DB를 수정하지 않습니다.
